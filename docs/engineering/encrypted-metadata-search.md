## Encrypted Metadata and Local Search — Prototype

## Research basis
- Room 2.8.4 supports DAO queries, transactions, and local persistence; KSP 2.2.10-2.0.2 matches the project's Kotlin 2.2.10 toolchain: https://developer.android.com/training/data-storage/room
- SQLCipher for Android 4.19.1 documents Room 2 integration through SupportOpenHelperFactory and supports API 23+: https://github.com/sqlcipher/sqlcipher-android
- SQLCipher Android uses a BSD-style license; required notices and license text are included under app/src/main/assets/licenses.
- SQLCipher must load its native library explicitly and can log through its Java/JNI/core layers. This implementation loads the native library before opening the DB and routes its Java logger to NoopTarget.
- The database passphrase is not hardcoded. A random 256-bit SQLCipher key is wrapped with AES-GCM under a separate Android Keystore alias and stored only in no-backup app-private storage.

## Data flow
1. The encrypted file payload remains the source of truth for the original document and OCR state.
2. On a worker thread, the repository decodes the encrypted payload and rebuilds/updates the SQLCipher metadata table.
3. The SQLCipher database stores the opaque document ID, display name, MIME type, byte size, last update timestamp, OCR engine score, review/truncation flags, and a normalized searchable copy of filename + OCR text.
4. The normalized search copy is sensitive data. It is inside SQLCipher, not a plaintext sidecar or a separate unencrypted FTS index.
5. Search queries are normalized in memory and passed as bound DAO parameters. Query strings are not logged.
6. Search returns opaque IDs; the repository re-reads the encrypted payload before returning a document result. Missing/stale IDs are ignored.
7. If the encrypted DB cannot open, the app falls back to scanning decrypted payloads in memory; it does not silently create a new database key or replace a corrupt wrapped key.

## Initial search semantics
- Unicode NFC normalization, lowercase with Locale.ROOT, and whitespace collapsing.
- Substring/phrase search over the normalized display name and OCR text.
- English, Hindi, and Telugu text is retained; there is no stemming, token ranking, fuzzy search, or transliteration/hinglish mapping yet.
- The v1 implementation rebuilds the metadata table from encrypted file payloads on each library refresh. This is simple and self-repairing but not optimized for large vaults.

## Key lifecycle
- Database key: 32 random bytes generated by SecureRandom.
- Key-encryption key: non-exportable AES key under Android Keystore alias kaagaz.vault.database-key-wrap.v1.
- Wrapped key: AES-GCM envelope with a dedicated AAD context and a file under noBackupFilesDir.
- Corrupt/missing-wrapper handling: if the wrapper exists but cannot authenticate or has the wrong size, fail closed. Do not silently generate a replacement because that would orphan the database.
- The database key remains in memory while Room is open and is zeroed when the provider closes. Java/SQLCipher may internally retain copies; this is not a guarantee of complete memory erasure.
- Database recovery/rotation, device credential binding, key invalidation recovery, and database export remain future design work.

## Limitations / acceptance gates
- Not yet CI-verified at the time of writing. Dependency resolution, KSP processing, SQLCipher JNI packaging, Room schema generation, runtime database opening, and merged-manifest policy must pass.
- No plaintext database should be created as fallback. Verify actual database, WAL, rollback journal, temporary files, and backup artifacts on-device.
- Database and document-file updates cannot be one atomic transaction. Encrypted payload files are the source of truth; library refresh rebuilds the index. Crash/recovery tests are still needed.
- Search currently scans a normalized field with SQLite instr() rather than FTS. This avoids a separate index design at first, but large-vault latency needs measurement before optimizing.
- No measured performance or security certification is claimed.
- SQLCipher key wrapper and database open behavior need Android instrumentation tests on API 23+ and a current Android version.
